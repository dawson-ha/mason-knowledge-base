# Obsidian + AI 知识库模板

我是在**弄懂知识库到底在干什么**之后，才搭出这套 Obsidian + AI **脚手架**的。知识库不会随 clone 一起送给你——它要在你的习惯里**慢慢长出来**（新卡先过一张样板、索引一点点追加），而不是第一天把文件夹塞满，也不是照搬别人的 vault。

下面先写**为什么**和**原理**；结构速查和快速开始在后半。细则以 [AGENTS.md](AGENTS.md) 为准。

---

## 我为什么做这个项目

GitHub 和 B 站上关于「知识库」的开源项目、教程很多。我跟过不少：第一步装什么、第二步建什么文件夹，跟完确实能把库**搭起来**。但我发现两件事没讲清楚：

1. **为什么这么搞**——你不明白，以后还是用不起来。
2. **知识库对你意味着什么**——没有积累和加工流程，搭出来的只是**对别人有用的演示**，对你自己**毫无意义**。

所以我开源的不只是一套数字文件夹，而是：**先把痛点和原理讲明白，再给你能直接用的脚手架**。你在上面长出来的，才是**你的**知识体系。

我自己要的是**长期能用的理解**，不是收藏夹。Obsidian 负责看网（双链）；Cursor、Codex、Claude Code 等打开**同一目录**，让 agent 按 [AGENTS.md](AGENTS.md) 做切分、索引、编译这类机械活；**判断、口吻、定稿在我**——尤其是每张卡片上的「我的理解」，我不过目就不算数。

结构上我**借鉴**了 Andrej Karpathy 的 [llm-wiki](https://gist.github.com/karpathy/442a6bf555914893e9891c11519de94f) 思路：原料 → 成品 → 规则，Obsidian 当浏览器。但成品层我拆成两条线（要内化的卡片 + 外来资料的 wiki），没有全盘交给「LLM 写整库」。原因见下文 Karpathy 专节。

还有一条我自己的底线：**MVP、小步、别越搞越复杂**。流程一旦「看起来很完备」，我反而容易放弃。这个仓库里只有**规则 + 空目录 + 卡片模板**，没有替任何人准备好的「示范知识体系」。

## 我看到的两个坑

### 坑一：照葫芦画瓢，只剩架子

教程往往停在「库跑起来了」：插件、同步、目录树，看着很专业。

但很多人并不清楚：**知识库到底是干什么的？** 它和网盘、随手笔记、「Second Brain」口号有什么区别？更缺的是**知识加工流程**——东西从哪进、怎么变成「以后真会拿来用」的、遇到具体问题时怎么**用回去**。没有这些，只有文件夹和链接，就是**照葫芦画瓢**：大家都说知识库有用，你也搭一个，可你没有知识积累，也不知道怎么加工，**架子对你没有意义**。

### 坑二：别人的库，变不成你的体系

**知识**可以迁移：一段话、一个链接、一篇文章，拷过来就行。

**知识体系**迁不走：你怎么切分、什么算「一条」、什么值得写进「我的理解」、什么只配留在参考里——这是**你构建的过程**，不是复制一个 `.obsidian` 配置就能得到的。

在我这里：**知识库 ≈ 你的知识体系本身**，不是「知识」的堆放处。Karpathy 那类方案把大量外来资料交给 LLM，**持续编译成可搜、可问的 wiki 页**——那很适合当**二级图书馆**；但若你从未建立自己的「我信什么、我会按什么行动」，clone 别人的 vault 或只堆 wiki，往往会**一脸懵**：缺的是**原理和习惯**，不是缺一个 repo。

所以要 **知其然，也要知其所以然**：先明白再搭。本仓库的定位是**明白原理之后的脚手架**——你在上面长出**属于你自己**的库。

## 知识库在这里指什么

**壳和网。** 前面的 `00`、`10`、`20` 数字文件夹是**壳**，方便排序和分工；真正的**网**在 `10k_cards/` 里：一张卡一个观点，标题就是文件名，卡与卡之间用 `[[双链]]` 连起来，再加上你会修订的「我的理解」。

**原料从哪来。**

- `00收件箱/`：随手记、AI 长输出，**不要求格式**，是未加工的入口。
- `20参考/`：第三方原文（摘抄、PDF 转 markdown 等），agent **不得改写内容**，顶多代转格式。

**两条成品线（并行，不是二选一）。**

| 路线 | 放哪 | 颗粒度 | 谁定稿 |
| --- | --- | --- | --- |
| 内化：要变成「我的判断」 | `10k_cards/` | 细，一卡一点 | **你**（agent 可起草） |
| 编译：外来、懒得细读、先要能搜 | `20参考/` → `wiki/pages/` | 粗，同一主题可反复更新 | agent 维护编译页，**不等于**「我的理解」 |

**加工不能省。** 不能把参考或 wiki 直接当卡片；也不能把 wiki 批量「翻译」成「我的理解」。值得内化的一句话观点 → 先进 `00收件箱/`（或你指定的原料）→ 再按规则收成卡。中间「消化」这一步跳过去，库就会充满**看起来像内化的 AI 讲义**。

**提问怎么用库。** 一次「基于卡片作答」的提问：问题记 `09问题/`（含调用了哪些卡、参考了哪些 wiki），答案写 `11输出/`。**先打开卡**答眼前这道题；以前的答案、wiki 摘要，都**不能**代替卡片当你的行动依据。

**练习。** `13练习/` 放对照表、切段、进度（例如学英语）。有的场景里**写卡本身就是练习**（AGENTS 里的模式 B），那种情况下 agent **不代写卡**——代写等于把练习归零。

**生长。** 批量新卡之前，先出 **1 张样板**，你确认口吻再让 agent 做一批。卡片索引 agent 默认**只追加**、不擅自改结构。库是**长出来**的，不是 import 一坨别人的笔记。

**和 AGENTS 对齐的两条流水线：**

- **卡片线（§4A）：** `00收件箱/`（或你点名内化的参考）→ 消化 → `10k_cards/` → 加工完的原稿可移入 `30归档/`（只进不出）。
- **编译线（§4B）：** `20参考/` → 编译 → `wiki/pages/` + 更新 `wiki/index.md`；同主题新原料**更新同一 wiki 页**，并追加「编译记录」。
- **规则层：** 只看 [AGENTS.md](AGENTS.md)。

## Karpathy 的 llm-wiki：适合什么、我为什么没有全盘用它

先说清楚：**不是 Karpathy 不好**，而是**目标不同**。我保留了他式 wiki 作为**编译线**；没有让整库只剩一种「LLM 写成品」。

### Karpathy 在解决什么问题

[llm-wiki](https://gist.github.com/karpathy/442a6bf555914893e9891c11519de94f) 描述的是：个人持续 **ingest** 大量外来信息（网页、PDF 等），让 **LLM 当 wiki 作者**——维护实体页、主题页，同一页随新原料**反复编译**，方便以后**检索、摘要、向库提问**。人主要做 **投原料 + 提问**，不必把每份资料都改写成自己的笔记。GitHub 上也有若干 llm-wiki 系实现，思路类似：自动化 ingest、索引、lint，wiki 越编越厚。

### Karpathy 特别适合的场景

- 资料**量大、更新快**，你**不打算逐字读完**，但需要以后**搜得到、问得到**。
- 你能接受成品是**「编译摘要 / 二级图书馆」**，而不是**「这话是我信的、我会按它行动」**。
- 你愿意把**判断**推迟到「到时候再问 LLM」，而不是现在就写进「我的理解」。
- 你的维护重心在 **ingest + 反复编译同一 wiki 页**，而不是**一张一张定稿卡片**。

如果你主要是这种需求，Karpathy 路线（或社区里的 llm-wiki 工具）往往更对口，**不必强行换成我的卡片-centric 流程**。

### 我为什么没有全盘用它

| 维度 | Karpathy / 全自动 llm-wiki | 本脚手架 |
| --- | --- | --- |
| 谁写「成品」 | LLM 全权维护 wiki | **卡片**必须**我定稿**；wiki 只服务外来摘抄 |
| 颗粒度 | 粗：一页多信息 | 细：**一卡一点**；旧卡可修订，并留修订记录 |
| 行动依据 | 容易变成「问了再说」 | **行动以卡片为准**；wiki、旧答案不能顶替卡 |
| 内化 | 统一口径的摘要，容易**显得**全懂了 | 强制走消化；参考/wiki **不能**直出「我的理解」 |
| 节奏 | 人轻，交给 LLM 簿记 | 故意**小步**：样板卡、一轮一批，避免「完备到放弃」 |

**一句话：** Karpathy 擅长**外包阅读与检索**；我这套在**拥有理解、指导行动、答「我咋看」**上加了**人的闸门**——不是否定 wiki，而是**不让 wiki 当整个知识库的主体**，只让它待在「参考编译」那一支（§4B）。

### 相对 Karpathy，本脚手架多出来什么

限定一下「好」：**如果你要在库里留下自己的判断、并用它指导行动**，下面这些是刻意设计的；如果你只要一个强大的只读资料 wiki，Karpathy 系可能更简单。

- **权威分界清楚：** `10k_cards/`（我的） vs `wiki/pages/`（他人资料编译）。混答时**先卡后 wiki**（AGENTS §3.2）；冲突时**以卡片为准**。
- **双流水线并行：** 同一库可以同时「懒得细读的先 wiki」和「要内化的慢慢成卡」，而不是只剩一种成品形态。
- **问答复利在卡上：** `09问题/` 记录这次调用了哪些卡；复利来自**网变密、卡被修订**，而不是 wiki 越堆越长却从没有定稿的「我的理解」。
- **练习与内化分离：** `13练习/` 是练用工具；模式 B 下**写卡即练**，agent 不代写。
- **仍然保留 Karpathy 式 wiki：** 不是「比 Karpathy 好所以不用 wiki」，而是 **wiki 是子系统**，外来摘抄该编译就编译。

**你怎么选（三问）：**

1. 这份资料我要不要**变成我的判断**？→ 要 → 走卡片线；不要、先检索 → `20参考` / wiki。
2. 我愿不愿意**为这句话负责**？→ 愿意 → 「我的理解」必须我改；不愿意 → 放 wiki，别伪装成卡。
3. 我是在**练技能**还是在**囤资料**？→ 练 → 模式 B + `13练习`；囤 → 至少进 `20参考`，别空建文件夹。

## 这个脚手架里已经帮你定好的东西

**给你：**

- 带语义的数字文件夹（收件箱、问题、输出、练习、参考、归档、卡片、wiki 等）。
- `10k_cards/_卡片模板.md`、空的 `知识卡片索引.md`、`wiki/index.md` 与 `wiki/pages/` 壳。
- [AGENTS.md](AGENTS.md)（当前 v1.6）—— agent 的唯一规则源。
- MIT 许可证。

**不给你：**

- 任何作者的私人笔记、成片示范卡、「下载就能用的知识体系」。

**你 clone 之后：**

1. Obsidian → 打开文件夹 → 选**本仓库根目录**（整个目录就是 vault）。
2. Cursor 等 → 同一目录作为工作区。
3. 随手记丢 `00收件箱/`；摘抄丢 `20参考/`；让 agent 按 AGENTS 加工。**新卡仍须先 1 张样板、你确认再批量**（§4、§6）。

## 这套东西是什么（结构速查）

细则以 [AGENTS.md](AGENTS.md) 为准。这里是简表：

- **你写的、要内化的** → `10k_cards/` 知识卡片（「我的理解」要你过目）。
- **网上摘抄、懒得细读的** → 原文 `20参考/`，编译成 `wiki/pages/`（可反复更新同一页）。
- **提问** → `09问题/` + `11输出/`；可卡片 + wiki 混答，**先卡后 wiki**。
- **练英语等** → `13练习/` 对照表、进度；相关卡片由你手写（模式 B）。

和「全自动 LLM wiki」的分工：上文 **Karpathy 专节**已说明——**卡片是你定稿的**；wiki 是他人资料的摘要层，**不能**代替「我的理解」。

## 规则只看一个文件

**[AGENTS.md](AGENTS.md)** — agent 接手先读它，再读 `10k_cards/知识卡片索引.md`。

不要用根目录的 `SCHEMA.md`（若你从别处拷来旧文件）——已废弃，以 AGENTS 为准。

## 快速开始

1. Clone 或复制本仓库到本地。
2. Obsidian → 打开文件夹 → 选本目录。
3. Cursor 等 → 打开本目录为工作区。
4. 随手记丢 `00收件箱/`；摘抄丢 `20参考/`；让 agent 按 AGENTS 加工（新卡要先样板、你点头）。

本仓库**不含**私人笔记，只有目录结构和规则。
